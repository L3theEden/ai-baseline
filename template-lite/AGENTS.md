# 需求分析精简基线 · AI 入口

用于读卡、与 Dev 澄清和整理需求共识。用户明确请求维护模板本身或另行指定任务时，按该请求处理。

## 先读与命令

先读 `.ai/README.md`，再按当前请求读取对应说明：

- `card-intake`（附卡号、标题与原文）：`.ai/workflow/01-card-intake.md`
- `clarify <卡目录>`：`.ai/workflow/02-clarify.md`
- `align <卡目录>`（可附 Dev 补充、资料或 BA 答复）：`.ai/workflow/03-align.md`

自然语言同样有效，三步可在同一聊天完成。clarify 沿设计树与 Dev 讨论，收敛后可直接整理结论；align 吸收新信息并继续讨论，无需切换命令。明确只读卡、只回填或暂停时按当前请求处理。

## 分析范围

- 只写 `.ai/cards/<本卡>/`，业务代码、测试、配置和数据只读；不自动运行项目、调用外部系统、pull、切分支、提交或推送。
- 新卡先建目录，已有卡先读 README、分析、澄清记录与结论再更新。卡号来自用户，目录与状态见 `.ai/cards/README.md`。
- 能查的事实由 AI 查证并附证据；Dev 暂时不确定时继续查证、推演或补资料。原卡明确的要求直接沿用，不因答复人是 Dev 就要求 BA 再确认。
- 与 Dev 讨论前置已明确的问题，回答后展开下一分支；技术取舍在 Dev 侧收敛，业务歧义或新增 / 改变业务规则、范围、验收时才提炼给 BA。问卷先供 Dev 审阅，由用户自行转发。
- 保存当前共识、关键依据和待办，区分事实、建议与决定；关键原话、来源及实质修订可追溯。每轮只简述变化、影响与下一步，不填重复复核表。
- 目标、范围、关键规则与 AC 已清楚且没有关键缺口时记 `answered`，无需 BA 问卷或额外签批。技术待查和待展开的关键分支不能靠改称后续项跳过。
- 收尾同步卡文件与状态，简述共识、未解问题和下一步。文档用中文，代码符号与路径保留原文。
