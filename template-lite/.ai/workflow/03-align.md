# 03 · 回填答复与整理结论

输入：本卡文档、用户提供的 BA / Dev 答复及其来源。产物：回填 `02-questions.md`，按 [结论模板](../templates/alignment.md) 创建或更新 `03-alignment.md`，同步 `README.md`。没有问卷或问题无法对应时，先识别对应关系；无法确定的答复记录为“待映射”，请用户指出对应题，不硬凑决议。

允许部分答复，允许多轮补充。记录答复就是本阶段的工作，不额外要求一次“批准回填”。

## 回填

1. 在各 Q 下记录原话、答复人、实际答复日期和来源（如用户转述、附件标题）。未提供的人名或日期写“未提供”，不把转述人自动认成 BA，也不补造日期。
2. 保留原答复，再单列“当前理解 / 决议”。只有能明确对应到该题且由有权者作出的答复才记“已答”；建议、含糊表达或冲突记“待澄清”。阻塞题遇到“按建议来”的笼统回复仍需明确结论；可默认题明确接受建议后记“按建议”，并保存当时接受的建议内容。
3. 对含糊答复，先写清可能的两种理解与影响，再提出最少必要的追问。部分答复先落档，不能因为一题未答就丢掉其他明确结论。
4. 新答复与旧答复冲突时，保留两者及来源。只有明确是在修订原决定且有相应权限时，才将旧结论标“已被取代”；否则保持冲突待确认。建议变化、范围变化或验收变化时核对所有受影响的 Q 和 AC。

## 每批答复后的复核

按 [问卷说明](02-clarify.md) 的“交互与逐轮复核”检查依赖、新场景、规则冲突和验收缺口，不只核对已有题是否填满。前置决定明确后，仍在范围内的待展开题必须继续展开；已排除的标“本期不适用”并引用依据。

新问题进入同一份问卷，Q 编号从已有最大编号递增；重开旧题时保留原答复及原因。把受影响的既有决议和 AC 标清，记录本轮变化与下一步。发现需要展开的关键问题时，先保存本轮明确答复和结论草稿，再进入下一轮；未获继续整理问卷的授权时，提示用户使用 `clarify`，不把开放项当成已经收敛。

## 整理当前结论

- 目标、范围内外、术语、业务规则与数据口径：每条关键结论引用 Q 编号或明确的卡片原文 / 确认来源。没有依据的内容标为建议或开放问题。
- 决议：记录 Q 编号、决定、答复方式（BA 答 / 有权 Dev 答 / 明确接受建议）、理由与来源。用户仅转述答复时按原答复来源记，不据此虚构其权限。
- 验收标准：用编号稳定的 `AC-1`、`AC-2` 等描述 Given / When / Then 可观察结果，标“已确认依据”或“草稿待确认”。明确的原卡标准也可作为依据；涉及未答关键题时只能写草稿。
- 疑点处置：需求价值质疑被采纳、否决还是未处理，保留决定与理由。关键疑点没有处置结论时仍属于开放问题。
- 开放问题与推迟项：分清未答关键题、待展开关键题、待澄清答复、技术资料缺口和可推迟细节，写清影响、负责人或资料来源。技术缺口会改变范围或验收时也阻塞收敛。

## 决定状态并结束

按 [状态规则](../cards/README.md) 判断：

- 只是部分答复，仍等关键答复：`awaiting-ba`。
- 范围已定，需要展开下一轮关键题：`clarifying`。在问卷中列出待展开题，不把它们当已解决；用户已要求补齐下一轮时，可继续执行 [问卷说明](02-clarify.md)。
- 所有阻塞题均有有权者的明确答复，关键范围、口径、验收已收敛，没有未处理关键疑点或待展开关键题，影响关键判断的技术缺口已解决：`answered`。可推迟细节要明确列出及说明影响。

汇报已确认的关键结论、明确按建议处理的题、仍需追问的 Q 编号和开放项。保持验收草稿与已确认部分的区别；仅“有答复”不等于“所有结论已正式批准”。如用户提供了明确确认原话，可在结论中记确认人、日期、原话及适用版本；后续实质变更则注明原确认不覆盖这些变更。

`answered` 是本流程终点。到此保留分析文档，不创建后续阶段产物。
