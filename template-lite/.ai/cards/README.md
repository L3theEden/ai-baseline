# 卡目录与状态

每张卡一个目录：`.ai/cards/<feat|fix|unknown>-<卡号>-<slug>/`。slug 从标题取少量英文词，使用 kebab-case；类型无法判断时用 `unknown`，并在读卡文档注明。

卡号来自用户。没有卡号时请用户给出原卡号，或明确指定一个本地分析标识，AI 不自编业务卡号。标识原文保存在 frontmatter；目录名里的路径分隔符等特殊字符转为连字符。

## 按进度生成文件

- `README.md`：卡片标识、状态、一段当前进度和下一步。
- `01-card.md`：原始卡内容、证据、影响面和缺失信息。
- `02-questions.md`：问题、推荐、逐题原文答复及轮次记录。
- `03-alignment.md`：当前需求结论、决议、验收标准与开放项。
- `assets/`：可选，用户提供的截图或样例。

多个仓库涉及同一卡时，选一个分析主仓库存文档，其余只作为资料来源记录路径；不要求在每个仓库重复建卡。

## `README.md` 起始格式

```yaml
---
id: "<用户提供的卡号或本地分析标识>"
workflow: analysis-lite
type: feat
title: "<卡标题>"
stage: intake
created: "<YYYY-MM-DD>"
updated: "<YYYY-MM-DD>"
---
```

frontmatter 后写一段话：本卡现在确认到哪里、尚缺哪些关键信息、下一步是什么。日期用实际日期；卡原文与答复日期不能用当前日期补造。frontmatter 字符串按 YAML 转义。

## 状态规则

- `intake`：读卡进行中，允许继续 `card-intake`。
- `clarifying`：读卡完成，正在交互澄清、整理或修订问卷，或需展开关键题、待细化领域及其前置。可使用 `clarify`；已有问卷时也可用 `align` 回填或续接对齐中的澄清轮次。
- `awaiting-ba`：问卷已产出，等待用户审阅、转发或补充答复；允许 `clarify` 精简 / 追问，或 `align` 回填。
- `answered`：用户目标与可观察的成功表现明确，所有阻塞题均有有权答复者的明确结论，关键冲突已解决，关键范围、口径与验收已清楚，且无待展开关键题或影响范围与 AC 的待细化领域、技术前置。未答业务题须由有权者明确决定推迟，技术未知项须由 Dev 评估可推迟，记录依据、影响和后续处理，且不改变本期范围或 AC。至此分析结束。

部分答复回填后仍等关键答复，保持 `awaiting-ba`；范围答复引出必须展开的新题，改为 `clarifying`，直接按设计树追问并整理下一轮，待 BA 问卷整理好后回到 `awaiting-ba`。`align` 内的状态变化不要求用户切换命令，每轮复核与答复持续落档。新增或修改关键题导致旧结论失效时，从 `answered` 回到相应未完成状态，并在文件里保留修订依据。

`answered` 的卡允许 `align` 追加记录或修订；若复核发现关键新问题，重开相应状态并直接继续追问，也可单独用 `clarify` 补充问卷。新增事实用 `card-intake`。重新读卡只更新事实，不清空问卷或结论，也不无条件重置状态。

已有同卡目录时先读取再追加，禁止重建覆盖。跨轮 Q 编号唯一且不复用；移出范围的题标“本期不适用”，保留其原文、答复和变更原因。历史结论被新答复取代时保留原记录与来源。

`workflow: analysis-lite` 标识本流程。缺少该字段或字段值不同的已有卡，先核对来源；确定是本精简版卡片后可补标，其他流程的卡仅在用户明确要求时迁移。这里只使用上述四个状态，读到其他状态时不静默映射。无需在答复收敛时自动移动或删除卡目录。
