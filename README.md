# AI 开发基线

把需求理解、业务决议、验收标准与项目知识写进仓库，让 AI 协作从已有事实和明确范围开始。

这是一套纯 Markdown 模板，包含流程手册、卡片文档模板和 AI 命令入口。按团队的 BA → Dev → QA 流程组织工作，可供读取 `AGENTS.md` / `CLAUDE.md` 的 AI 编码工具使用。流程执行依赖工具读取并遵守文档，关键业务决定仍由有权者确认。

## 选择适合的版本

- **[精简版 `template-lite/`](template-lite/)**：适合只做读卡、澄清、BA 问卷和答复整理。按卡查证项目事实，只维护本卡文档，不必先建立全量规范库。关键问答收敛后记为 `answered`，分析结束。
- **[完整版 `template/`](template/)**：适合继续完成开发计划、开发与评审、DC（Desk Check）演示、QA 测试和结卡。包含项目规范、上下游上下文、决策与日志目录；需求对齐后须明确批准，再进入开发计划。

两个版本共用 `.ai/` 和阶段命令名，**同一业务仓库选择一套流程**。已有完整版时也可只使用前三阶段；切换成精简版时，按[精简版使用指南](03-精简版使用指南.md)核对并迁移卡片状态。

## 快速接入

先在业务仓库之外下载模板库，将 `/path/to/ai-baseline` 替换为实际保存路径：

```bash
git clone https://github.com/L3theEden/ai-baseline.git /path/to/ai-baseline
```

进入**目标业务仓库根目录**。仓库尚无同名 AI 配置时，选择下面一种模板复制；命令会包含隐藏目录。

精简版：

```bash
cp -R /path/to/ai-baseline/template-lite/. .
```

完整版：

```bash
cp -R /path/to/ai-baseline/template/. .
```

已有 `AGENTS.md`、`CLAUDE.md`、`.ai/` 或同名 skills 时，先合并并核对现有内容，按下文的[升级说明](#已有项目怎么升级)处理。

复制后，精简版可直接从一张卡开始；完整版先按[推广指南](02-推广指南.md)登记模板来源提交与项目适配，填写项目入口和 `spec/`、`context/` 中的事实。占位骨架与虚构示例不能当成项目现状。

## 从第一张卡开始

以下内容输入到 AI 聊天中。Claude Code 可使用对应的 `/<命令>`，其他工具可直接说出命令名或流程文件路径。

**1. 读卡并查证事实。** 卡号和内容来自实际需求；AI 返回卡目录路径，后续都使用这个路径。

```text
card-intake

卡号：<真实卡号>
标题：<卡标题>
卡内容：<BA 原文>
验收标准：<原文；没有就写未提供>
相关材料：<已有文档、样例或对端仓库路径>
```

**2. 启动澄清，整理本轮 BA 问卷。**

```text
clarify <卡目录>
```

默认先与 Dev 按设计树分轮澄清：先明确目标和范围，再问前置条件已满足的问题。Dev 不知道或无权决定的内容留给 BA；本轮问卷由 Dev 审阅后自行转发。

**3. 回填答复，持续复核与追问。**

```text
align <卡目录>

答复人：<姓名或角色>
答复日期：<实际日期；未提供就注明>
对应问卷轮次 / 版本：<知道则提供；不知道可省略>
答复原文：<可分批粘贴，最好带 Q 编号>
```

启动 `align` 后，同一聊天直接回答新问题或补充 BA 答复即可继续。发现新问题会自动按设计树追问，**无需手动切回 `clarify` 或重复输入 `align`**。换聊天时提供卡目录，用 `align <卡目录>` 读取文件续接需求问答。

需要直接出问卷时，可以说“跳过交互，整理本轮 BA 问卷草稿”；只想保存答复时，可以说“只回填，先不追问”。未解决的问题会保留。

精简版在关键问答全部收敛后记为 `answered`，结束分析；完整版在关键问题收敛后呈现最终摘要，收到后续消息中的明确批准，才放行 `dev-plan`。开发计划另有设计确认和拆解确认，拆解确认后才可开始实现。

## clarify 和 align 的分工

- **`clarify`：确定需要问清什么。** 从需求卡和已有证据出发，澄清目标、范围、规则与边界，整理有依据、有依赖关系的本轮问卷。适合首次拆需求，或主动补充、重整问卷。
- **`align`：确定最终做什么、如何验收。** 从已有问题和答复出发，回填原话、核对来源与版本，整理范围、决议和可观察的验收标准；发现缺口时复用澄清方法继续下一轮。

每批答复后，AI 都应呈现简短的复核依据：解锁了哪些问题、推演了哪些相关场景、是否存在冲突、验收是否覆盖，以及当前需要继续追问、等待答复 / 资料，还是已经收敛。

**生成文档或答满当前问卷，不等于需求已经收敛。** 还要检查被资料阻塞的关键题、范围内尚无法准确提问的领域、关键冲突和验收缺口。技术资料只阻塞依赖它的问题，其他独立题继续处理；额外能力留作后续建议。

问题编号跨轮保留，题干或建议实质修订时记录版本，异步答复核对其对应内容。未答业务题的推迟须有有权者的明确决定，技术未知项须由 Dev 评估；影响本期范围或验收的缺口仍须解决，或先明确修订范围与验收。后续出现关键新问题时重开分析，保留旧结论与修订依据。

## 流程与产物

精简版：`读卡 → 澄清 ↔ 对齐 → answered`。

完整版：`读卡 → 澄清 ↔ 对齐 → 开发计划 → 开发与评审 → DC → QA / 结卡`。

完整版默认分阶段使用会话，02 澄清与 03 对齐可以连续问答；后续阶段仍由用户显式触发。完整命令、状态和门禁见[流程总览](template/.ai/workflow/overview.md)。

每张卡在 `.ai/cards/` 下有独立目录，随进度生成文件。以下目录名为虚构示例：

```text
.ai/cards/feat-DEMO-123-task-status-filter/
├── README.md          # 卡片标识、状态、当前进度与下一步
├── 01-card.md         # 卡原文、事实核实、影响范围与缺失信息
├── 02-questions.md    # 问题、原文答复、版本与逐轮复核记录
└── 03-alignment.md    # 当前需求结论、范围、决议、验收与开放项
```

完整版后续增加开发计划、`tasks/` 子任务单、开发与评审记录、DC 文档。04 列文档影响，05 随实现更新项目知识并评审，06 核对验证范围，结卡时提炼经验和归档。换工具或换会话时，从卡目录续接。

项目规范与共享契约维护现行结论，本卡未来方案保存在已批准的 03/04，历史保留证据指针。关键事实注明来源与核实范围，分别记录代码已实现、已部署和环境已验证；具体见[项目文档维护](template/.ai/workflow/documentation.md)。

## 已有项目怎么升级

升级模板时，先查看差异，再按项目实际内容合并：

1. 比较并合并所选版本的 `.ai/workflow/`、`.ai/templates/` 和 `.ai/cards/README.md`，保持流程与产物格式一致，保留项目适配。
2. 合并 `AGENTS.md`、`CLAUDE.md`、`.ai/README.md` 的入口规则，保留已填写的项目信息；核对 `.agents/skills/` 与 `.claude/skills/` 是否仍指向对应流程。
3. 保留实际卡片、项目规范、上下游上下文、决策和日志，尤其是 `.ai/cards/<实际卡>/`、`.ai/spec/`、`.ai/context/`、`.ai/decisions/`、`.ai/journal/` 中的项目内容。
4. 对已有问卷且仍在需求问答中的卡，用 `align <卡目录>` 续接；若新规则发现关键缺口，如实重开并记录受影响结论。

**完整版**在 `.ai/README.md` 登记来源仓库、模板目录、来源提交、最后完整同步日期及项目适配。升级按[来源与升级协议](template/.ai/workflow/baseline-upgrade.md)比较“旧模板、当前项目、新模板”；旧来源不明时逐文件核对并保留项目内容，部分升级单独记录，完成后才更新来源版本。修改本模板库不自动升级任何业务项目。

## 业务资料与对外分享

本仓库用于维护通用模板，实际业务资料留在目标业务仓库。文档中的任务管理场景、`DEMO-*` 卡号和示例代码路径均为虚构示例。

卡片、日志、接口样例和项目规范可能包含内部信息。对外分享前同时检查文件与 Git 历史，用虚构示例替代真实业务数据，并移除内部地址、个人信息与凭证。
