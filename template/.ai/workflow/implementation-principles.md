# 最小实现与修复原则

完整流程与轻量维护共用本说明。先理解本次目标、有效 AC / 契约和实际代码路径，再选择实现；本说明不改变阶段批准、可改文件、提交推送授权或轻量升级条件。项目约定在 [conventions](../spec/conventions.md)，与通用建议冲突时查明依据并记录适配，不能自行降低验收要求。

## 最小实现阶梯

沿以下顺序查证，找到满足本次行为、兼容性和项目约束的方案即可停下；现有模式只是候选，不能因为已经存在就复制其缺陷。

1. **确有必要吗？** 对应哪条 AC 或既定行为，不做有什么后果？没有当前依据的候选留在范围外；已要求的行为若建议取消，须先按原流程修订范围。
2. **仓库已有吗？** 搜索已有函数、类型和同类实现，确认语义、边界和调用约定一致后复用；外形相似但职责不同的不强行合并。
3. **标准库能满足吗？** 核对当前运行环境的能力与边界，避免重写已具备的能力。
4. **平台原生能力能满足吗？** 在兼容性、可访问性和契约允许时使用平台提供的能力。
5. **已安装依赖能满足吗？** 核实项目实际版本与用法；已有依赖不能满足时才论证新增，新依赖仍按计划变更或维护升级规则处理。
6. **写最小且清晰的实现。** 只实现当前需要的行为，不预建无人使用的抽象、配置和扩展点；不以一行代码、文件数或净减行数作为通过标准。

简化不裁剪 AC、契约、信任边界校验、防止数据丢失的错误处理、安全和可访问性要求。测试按受影响行为与项目门禁确定，复用足够的已有覆盖，不设“一项检查就够”的上限。方案选择的必要理由写入原有计划 / 维护记录，不另建阶梯报告。

## 修复前核查调用链

行为缺陷在修改前完成以下核查，纯文字 / 链接纠正只做对应内容检查。围绕本次目标追踪，不扩展为无关的全仓库治理。

1. **从现象追到行为所在处。** 根据有效预期与复现证据，沿入口、调用、数据读写和结果返回定位相关路径与符号，区分已证实的根因和待验证假设。
2. **查相关调用方。** 用符号引用、`rg` 等检索待改函数 / 模块的调用点；涉及路由、回调、事件、反射或配置绑定时补查对应入口。记录检索范围、调用关系、源码修订与证据；没有静态命中不等于没有调用方，必要路径不可见时保留缺口。
3. **逐项判断影响。** 记录哪些调用方受影响、哪些不受影响及原因，核对它们是否真的共享相同期望。共享行为有缺陷时优先在行为归属处修一次；调用方语义不同的，保留其边界，不机械地把判断下沉到公共函数。
4. **确定修复与回归边界。** 写清拟修位置及理由，覆盖报错入口、其他受影响入口和需要保持的行为。代表用例可合并，但须说明覆盖关系；必要调用关系或预期不清时，不凭一个入口通过就宣告修复完成。

完整流程将核查结论记入 04，子任务引用并在开工时核对当前修订；轻量维护记入 `maintenance.md`。核查允许与本任务有关的只读检索，不扩大写入权限。执行者发现新影响交协调者补单 / 重新确认；轻量发现影响扩大按 [维护分流](maintenance.md#必须升级的情况) 处理。可复用已核实证据，无需每次重抄整条链路。

## 有意简化的边界

仅为**有已知限制、但能满足当前验收与约束**的取舍留记录；正常复用标准库、删除无需求代码不自动算作技术债，也不为未知未来制造待办。每项简短说明：

- **当前为何足够**：适用范围、依赖的前提和证据；拟采用还是已实现分别标明。
- **已知上限**：已确认的规模、时延、兼容性或其他限制；未知数字如实标注，不虚构容量 / 性能结论。影响本次验收或维护适用性的未知项须先核实。
- **重新评估条件**：可观察的变化或事件及核查方式，例如超出已有性能预算、支持范围改变、原前提不再成立；阈值须有来源，不只写“以后优化”。
- **届时处理方向**：需要重新调查或比较的方案，以及记录去向；只是后续评估入口，不构成自动扩展范围或实施的授权。

完整流程写入 04 的“简化方案及重新评估条件”；轻量写入维护记录对应项。实施并验证后，持续存在的限制写回 [legacy](../spec/legacy.md)，保留批准 / 授权及证据指针，卡内记录作为历史。现行状态只维护一份；只有符合 [ADR 条件](../decisions/README.md#adr--架构决策记录) 的取舍另立 ADR。易误用的代码处可沿用项目注释风格简述限制并指向主记录，不要求统一标记或新增扫描工具。

后续卡触及相关区域时复核前提与触发条件；条件已满足就记录实际影响，按本次范围重新评估和分流，不直接执行旧记录里的方案。限制解除时在主记录补解除依据并标“已解除”。本次 AC、安全要求或必需验证尚未满足的问题不能包装成简化取舍留到结卡之后。

虚构示例：某列表在当前已验证数据范围内采用线性扫描，覆盖原有筛选语义；现行性能预算见该虚构项目的测试规范。实测超出预算或数据范围扩大时，重新比较索引 / 查询方案并评估改动风险。例子不提供通用规模阈值，也不代表任何真实项目事实。
