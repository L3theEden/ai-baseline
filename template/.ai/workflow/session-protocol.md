# 会话协议（Session Protocol）

本基线按"一个窗口只做一个阶段"运行。窗口就是一次 AI 会话，工具和模型都可以换（Kimi、Codex、Claude Code、Cursor 等）。所有窗口遵守同一套开场与收尾动作；阶段之间只靠卡目录里的文件交接，不靠聊天记录。

## 在哪里启动

- 在**主改动仓库的根目录**启动 AI 工具（跨仓库卡通常是主改动仓库）。多数工具只从启动目录加载 `AGENTS.md` 和 skill 目录（`.agents/skills/`、`.claude/skills/`）；在两个仓库的上层目录启动，入口与阶段命令都不会加载。
- 执行子任务时，在子任务单写明的"工作目录"启动（可能是另一仓库，或本地临时 worktree）。

## 开场（每个窗口都做）

1. **确定卡目录。** 来自阶段命令的参数；没给就列出 `.ai/cards/` 下未归档的卡与各自的 `stage`，请用户指定，不要猜。
2. **核对 stage。** 读卡目录 `README.md` 的 `stage`，按下表确认本窗口能做的阶段。与用户的命令或说法不匹配时，告诉用户当前该执行哪个命令，然后停。
3. **拉最新代码。** `git pull`（主分支开发）；pull 出冲突先停下解决。**执行者窗口不 pull**：worktree 的本地临时分支没有上游，主工作区的代码同步由协调窗口负责；执行者只在当前工作目录的现状上工作。
4. **只依据文件。** 只读该阶段手册列出的输入，不依赖聊天记录，包括本工具以前的会话。

| `stage` | 本窗口能执行的阶段命令 |
|---|---|
| 无卡目录 | `card-intake` |
| `intake` | `clarify` |
| `clarifying` | `clarify`；已有问卷且用户显式输入 `align` 并提供答复时，可先回填并复核 |
| `aligning` | `align`；用户显式输入 `clarify` 补充或修订问卷时回到 `clarifying` |
| `planning` | `dev-plan` |
| `ready-for-dev`、`in-dev` | `develop`；`execute-subtask`（子任务状态须为"待执行"或"返工"）；`card-review <卡目录> spec` / `standards`（`in-dev`，集成评审已通过） |
| `desk-check` | `desk-check` |
| `in-qa` | `qa-handoff` |
| `done` | 无，卡已归档 |

02 的交互轮次可以在同一窗口继续，进度逐轮落档；从 02 切到 03 仍需用户输入 `align`。03 发现新问题或解锁待展开题时，先保存明确答复与草稿，改为 `clarifying` 并提示 `clarify`，不自行开始下一阶段。后续阶段发现影响已批准需求的关键问题时，按 `overview.md` 回流，修订重新批准前不继续依赖旧结论的实现。

## 收尾（每个窗口都做）

1. 本阶段产物写进卡目录；`README.md` 的 `stage` 与 frontmatter 下"现在到哪一步、下一步是什么"一段话同步更新。执行者窗口不改 `README.md`，见 `05-execute-subtask.md`。
2. 按 `journal/README.md` 追加 journal 条目。执行者窗口可以省略，由协调窗口汇总。
3. 打印"下一步"，然后结束本轮：

   ```
   下一步
   - 卡目录：.ai/cards/<卡目录>/
   - 当前 stage：<值>
   - 需要人做的事：<例：把 02-questions.md 发给 BA / 审阅开发计划后回复"计划通过" / 确认提交计划>
   - 下一个窗口：在 <仓库或工作目录> 启动，输入 <阶段命令> <卡目录> [子任务编号]
   - 建议模型：<顶级 / 低端>
   ```

## 不可让步

- **AI 永远不自行进入下一阶段。** "继续""没问题就开发""按计划做完"都不构成进入下一阶段的指令；只提示用户开新窗口执行对应命令。
- 用户坚持在同一窗口继续下一阶段时，必须显式输入该阶段命令；AI 按该阶段的开场重新执行（重读文件、核对 `stage` 与批准记录），不沿用本窗口的推理结论。
- 批准必须是 AI 呈现最终摘要**之后**用户发的一条新消息。最初的请求、建卡时的同意、"没问题的话就……"这类条件句都不算批准。

## 阶段中途换窗口

上下文快满、要换工具或交给同事时：

1. 先把进度写进本阶段产物（未完成的项标"进行中"），不要只留在聊天里。
2. 需要可移植的交接时，在卡目录写 `handoff-<日期>.md`：卡路径与 `stage`；已完成的事实与决议只写指针（哪个文件哪一段），不复制内容；进行中的事、下一步、卡在哪里；新窗口先读哪些文件；已知假设与风险。不含 token、secret、个人敏感信息。
3. 新窗口按开场协议启动，先读卡目录再读交接文件，冲突以卡目录为准。

## 权限模式

- 对齐、制定计划、协调评审窗口不要开自动批准（如 yolo）：这些窗口的价值就在人在环。
- 执行窗口可以开自动批准：改动范围被子任务单锁住，结果还要过评审。
