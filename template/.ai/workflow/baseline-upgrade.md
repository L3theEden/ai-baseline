# 完整版基线来源与升级

用于首次登记来源或用户要求升级完整版时。来源信息保存在 [`.ai/README.md`](../README.md#基线来源与项目适配)，本说明定义文件归属与合并方法。升级维护流程文件，不改变既有卡的阶段、批准或验收结果。

## 文件归属

下表是默认清单；项目有定制时，在 `.ai/README.md` 的“项目适配”登记具体文件 / 章节与保留原因。目录名相同不代表其中所有文件都归模板管理。

| 类别 | 文件范围 | 升级处理 |
|---|---|---|
| 通用流程与格式 | `.ai/workflow/`、`.ai/templates/`、`.ai/cards/README.md`、`.ai/journal/README.md`、`.ai/decisions/README.md`、`.ai/decisions/rejected/README.md` 中由旧 / 新模板提供的文件 | 三方比较后合并；上游新增文件先检查同名冲突，保留项目适配及项目独有文件 |
| 基线阶段入口 | `.agents/skills/`、`.claude/skills/` 下本基线的 `card-intake`、`clarify`、`align`、`dev-plan`、`develop`、`execute-subtask`、`card-review`、`desk-check`、`qa-handoff`、`maintain` | 只合并这些命令对应的原模板文件；其他 skills 保留 |
| 混合入口 | `AGENTS.md` 的 `AI-BASELINE` 区块、`CLAUDE.md` 的入口引用、`.ai/README.md` 的导航 | 合并流程部分，保留项目介绍、硬规则、命令、来源登记和适配记录；区块标记不是整段覆盖许可 |
| 项目知识与记录 | `.ai/spec/`（含索引）、`.ai/context/`、决策条目、实际卡目录和归档、journal 条目 | 保留项目内容；新规则需要调整结构时逐项迁移，不能用空骨架替换 |
| 其他项目文件 | 上述范围外的文件、入口区块外的人工内容、额外配置与 skills | 保留；不因同目录或上游删除而自动删除 |

## 首次登记

1. 从实际复制的模板仓库读取 `git rev-parse HEAD`，记录仓库来源、`template/`、完整提交号及实际同步日期。来源提交指模板仓库提交，不是业务仓库提交。
2. 确认复制内容对应该提交。若模板来源有未提交修改，来源修订记“未登记”，单列已知基础提交与所用文件差异 / 快照的位置；不能仅登记 HEAD 就声称修改已包含在该版本里。快照放在项目受控位置，包含本次使用的模板文件即可。
3. 登记项目化修改，例如分支策略、构建门禁、卡号格式、删去不适用的跨仓库章节。它们属于正常适配，升级时逐项保留或重新判断。

## 已有项目升级

1. **确认范围与工作区。** 只处理用户指定项目和版本。记录现有改动，保留可恢复的项目快照或提交；不把用户已有未提交内容混入升级，也不自动提交、推送或同步其他项目。
2. **确定三份材料。** 读取 `.ai/README.md` 登记的旧来源修订，取出该修订的 `template/`；再准备项目当前文件与目标提交的 `template/`。目标来源须能解析成固定提交，比较时不使用会移动的分支名作为唯一依据。
3. **三方比较并处理。** 比较“旧模板 → 新模板”识别上游变化，比较“旧模板 → 当前项目”识别项目适配。按上表逐项合并；两边改了同一规则时，明确最终行为并检查引用。上游新增同名文件或删除旧文件也先判断项目用途；有无法判断的取舍，只留下受影响项待确认，其余独立项继续。
4. **核对联动。** 入口、流程、产物模板和双份阶段 skills 要一致；新引用存在。项目 `spec/index.md` 与 context 的必要指针按新规则调整，现有项目事实、卡状态与批准记录保留。已有卡采用新文档字段时，按已知证据补录，未知项照实写明，不补造历史批准或验证。引入轻量维护时，旧卡缺省仍为 `workflow: full`；升级基线不自动将任何卡改成轻量，已有同名 `maintain` skill 先核对来源与冲突。
5. **完成后登记。** 合并核对完成，且所有相关差异已合并或明确记为保留的项目适配，才把来源修订更新为目标完整提交号并填写同步日期。同步记录写旧 / 新修订、改动范围、保留适配与验证结果。只完成部分时保留原来源修订，在同步记录标“部分”，列已处理文件、待处理项及目标提交。

### 旧版本不明或无法取得

- 不根据文件日期猜版本，不以“看起来相同”伪造来源提交。先检查项目 Git 历史和已有快照能否找回复制来源。
- 找不到时，将来源修订保留为“未登记”，以当前项目快照为保护基点，逐文件与目标模板人工比较；现有项目内容一律按需保留，明确处理每个差异。
- 完成文件归属清单内的全量核对后，可从目标修订建立新的来源记录，并注明旧来源不明、人工核对范围。未核对完整时仅记部分升级。

## 完成检查

- 来源修订可解析，且与实际采用的模板内容及适配记录相符；部分升级明确列出缺口。
- 项目知识、现有卡、日志、独有 skills 和人工入口内容均有保留；文件删除都有明确依据。
- 入口到流程、流程到模板的引用可用；`.agents` / `.claude` 对应命令内容一致。
- 共享契约若在本次授权范围内同步，按 [项目文档维护](documentation.md#跨仓库契约) 核对来源修订和各端状态；来源版本一致并不证明业务内容正确。
- 项目经验回馈公共模板时，只提炼通用规则或另写虚构示例，检查差异中的业务标识、内部路径、地址、数据与凭证。
