# 缺上下文协议（Missing Context）

AI 先从可读的代码、配置、文档及已知对端路径查证。以下情况经查证仍缺必要资料时，再与 Dev 明确缺口及补齐方式；其余独立工作继续，不因规范未登记就停下提问。技术未知由 AI / Dev 或相关技术负责人查清，只有业务判断缺口才提炼给 BA。

澄清与对齐中，影响范围、关键规则或 AC 的技术前置不能靠“按假设继续”宣布收敛；先记录缺口并处理其他分支。轻量维护遇到影响适用性或验收的关键未知项时，按 [维护协议](maintenance.md) 查证、阻塞或升级。

## 触发条件

- 卡引用了 `.ai/spec/` 未记载的模块、字段、状态、定时任务或系统。
- 需要改对端仓库（前端 / 后端）而对端的现有行为或契约不清楚。
- 涉及 `.ai/context/upstream-downstream.md` 里的系统，但该条目缺少本卡需要的信息（接口形状、失败表现、限流、字段含义）。
- 涉及历史包袱但 `.ai/spec/legacy.md` 没有解释"为什么会这样"。
- 涉及其他内部系统（如共享数据库、其他团队的服务）。

## 提示话术（固定格式）

```
缺少上下文：<具体缺什么，一句话>。
需要它来：<决定什么 / 避免什么错误>。
可选：
A. 我读取 <路径>（对端仓库 / 其他仓库 / 文档），预计要看 <哪些文件>。
B. 请回答：<1–3 个具体问题，每个可以答"不知道">。
C. 按假设「<假设内容>」继续，并在文档里标注为假设，DC 时提醒 QA 验证。
```

给出 A 之前先确认路径存在（`.ai/context/related-projects.md` 登记的本地路径）；路径不存在就不要提供 A 选项，改为请用户提供路径或仓库地址。

## 用户选择后

- **A**：读取后把结论写进本卡 `context-notes.md`（来源路径、读到的事实、对本卡的影响）。可复用的部分沉淀到 `.ai/context/` 对应文件；对端契约写进 `api-contract.md`。
- **B**：把问答原文记进 `context-notes.md`；可复用的沉淀方式同上。
- **C**：在 `01-card.md` 或 `03-alignment.md` 的相关位置标注"假设"，在 `06-desk-check.md` 的"未覆盖与已知限制"里列出，请 QA 验证。

## 不要做的事

- 不要在没有证据的情况下描述对端或上下游的行为。
- 不要因为缺上下文而停止所有工作；先做不依赖它的部分。
- 不要把用户的一次性回答只留在聊天里；写进文件。
- 执行者（`05-execute-subtask.md`）不走本协议向用户提问：缺上下文就在子任务单里标"阻塞"，由协调窗口处理。
