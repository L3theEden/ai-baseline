# 思考清单（Guides）

不管什么卡，开发前过一遍。每条都附证据路径——发现某条过时了，同卡改掉。

## 搜索优先

- 改任何常量、配置键、枚举值、日志前缀、URL 路径之前，先全仓 grep 它的所有引用点；跨仓库共享的还要 grep 对端仓库。
- 判断"某个功能有没有已经存在"：先搜入口（路由 / Controller / 菜单），再问用户。

## 跨层与跨仓库

- 一个行为横跨多层时，改动边界要写到最深一层；只改中间层经常漏掉最底层的字段映射。
- 跨仓库同卡的改动按"契约先行"：先定 `../context/api-contract.md` 的变更，再各端实现。

## 别做

- 别为"可能会用到"的场景加抽象（策略、接口、配置项）：AC 没写的不做。
- 别顺手整理无关代码；看不顺眼的记下来，写进卡的"范围外"或提新卡。
