# 历史包袱（Legacy）

每条格式：现象 / 原因（知道的才写）/ 影响 / 处理建议 / 证据 / 状态（已知接受 | 待修 | 待确认 | 已解除）。新发现的包袱先加在这里，结卡时决定是否提炼成 ADR 或修复卡。标注「待确认」的条目，先查代码与已有依据；仍缺必要信息时按 [缺上下文协议](../workflow/missing-context.md) 求证并回填。

已实施的有意简化方案若留下持续限制，按 [简化边界规则](../workflow/implementation-principles.md#有意简化的边界) 记入同一条目，引用原计划 / 维护记录与有效批准 / 授权。相关卡后续触及该区域时核对前提和重新评估条件；触发后更新实际影响与处理结论，后续实现仍按本次分流和授权。限制解除时标“已解除”并留解除证据。未来方案留在卡内，阻塞当前验收的问题不能标“已知接受”来结项。
