# `journal/` · 会话日志

记录每次 AI 协作会话做了什么、发现了什么、教训是什么，让下一次会话（可能是另一个人、另一个工具）从真实脉络开始。

## 文件组织

- 按开发者分目录：`journal/<git user.name>/YYYY-MM.md`。多人并行不冲突。
- 每个会话结束追加一条，条目模板见 `templates/journal-entry.md`。
- 单文件超过约 500 行时新开下一个月的文件即可，不做别的切分。

## 什么时候写

- 每张卡每个阶段结束时（哪怕只是读卡）。
- 会话交接前。
- 发现了值得记的坑，哪怕卡还没结。

## 每月提炼

每月（或每个迭代结束）把本月 journal 过一遍，问三个问题：

1. 有没有重复出现的坑 → 进 `spec/legacy.md` 或 `spec/guides.md`。
2. 有没有已经成为默认做法的约定 → 进 `spec/conventions.md`。
3. 有没有做过难回头的决定 → 进 `decisions/adr/`。

提炼过的条目在 journal 里标 `[已提炼 → spec/xxx.md]`，不删除。

## 不写什么

- token、密码、内网地址以外的敏感信息。
- 复制大段代码或文档；写指针。
- 与本项目无关的个人备忘。
